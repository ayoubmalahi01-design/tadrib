# THE TRAINERS — تقرير الأمان

## 1. نموذج الحماية بثلاث طبقات

1. **الواجهة**: إخفاء ما لا يحق للمستخدم (تجربة استخدام فقط).
2. **منطق التطبيق**: دوال نقية مثل `canEditReport` / `canReviewReport` في
   `src/lib/report-workflow.ts`، و`canManageGroup` في `src/lib/chat-utils.ts`،
   وبناء صفوف الحضور في `src/lib/attendance.ts`.
3. **قاعدة البيانات**: سياسات RLS (53 سياسة) وسياسات Storage. هذه هي الطبقة الملزمة.

إخفاء زر ليس حماية، والتحقق في JavaScript وحده ليس حماية.

## 2. المصادقة ودورة حياة الحساب

| الحالة | السلوك |
| --- | --- |
| بيانات خاطئة | رسالة عامة دون كشف وجود البريد |
| حساب بلا ملف تعريفي | رسالة مستقلة (لا يُعامل كقيد انتظار) |
| قيد الانتظار | شاشة انتظار، لا وصول للبيانات |
| مرفوض | رسالة رفض صريحة (كان يُعرض خطأ «قيد الانتظار» — أُصلح) |
| موقوف | شاشة إيقاف |
| فشل قراءة الملف | خطأ قابل لإعادة المحاولة، لا يُفسَّر كقيد انتظار |

الحالات مغطاة بـ `tests/account-gate.test.ts` (8 اختبارات).

## 3. عزل المؤسسات

- كل جدول تشغيلي يحمل `institution_id`.
- السياسات تقارن المؤسسة عبر دوال `security definer` لتجنّب الاستعلامات الدائرية.
- مسارات Storage تبدأ بـ `institution_id/`، والسياسة تتحقق من المجلد الأول.
- لا توجد سياسة تسمح لمالك المنصة بقراءة محتوى دفتر المدربين.

## 4. خصوصية دفتر المدرب

`coach_notebooks` مقيّد بـ `owner_id = auth.uid()` لكل عمليات القراءة والكتابة والحذف.
لا توجد سياسة للإدارة ولا لمالك المنصة. الإخفاء في الواجهة إضافة، وليس الحماية.

## 5. المحادثات والمرفقات

- قراءة الرسائل تتطلب عضوية في `conversation_members` (سياسة على `messages`).
- `message_reads` تسمح بتسجيل قراءة المستخدم لنفسه فقط.
- رفع الملفات: `trainer-media` يتطلب عضوية المحادثة ومطابقة المؤسسة والمستخدم.
- حذف الملف: المرسل فقط.
- الملفات الطبية: `trainer-medical` للإدارة فقط.
- الحد الأقصى 25 MB، والأنواع المسموحة محددة (JPEG/PNG/WebP/PDF/صوت).

## 6. سجل التدقيق

- الإدراج آلي من التطبيق.
- لا توجد سياسة تعديل أو حذف للمستخدمين العاديين.
- لا يُسجَّل محتوى دفتر المدرب الشخصي في سجل متاح للإدارة.

## 7. إدارة الأسرار

- المتغيرات العامة الوحيدة: `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
- **لا يوجد** مفتاح service-role في العميل ولا في أي `VITE_*`.
- لا توجد مفاتيح أو كلمات مرور في المستودع أو في ملف ZIP.
- ملفات `.env` الحقيقية مستبعدة من الحزمة.

## 8. المدخلات والعرض

- React يهرّب النصوص تلقائياً؛ لا يوجد `dangerouslySetInnerHTML`.
- الطلبات تُبنى عبر عميل Supabase (استعلامات مُعاملة، لا تركيب SQL نصي).
- التحقق من المدخلات في النماذج (حقول مطلوبة، أعداد غير سالبة، تواريخ صحيحة).
- منع الإرسال المزدوج عبر حالات `busy`.
