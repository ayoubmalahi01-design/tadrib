# حالة المشروع — THE TRAINERS | تدرّب

## مكتمل في الكود (غير مجرَّب على خدمات حقيقية)
- تسجيل الدخول والتوجيه حسب الدور والحالة (pending / active / rejected / suspended).
- لوحة مالك المنصة، المؤسسات، دعوات الفريق عبر Edge Function (المدرب يدعو مدرباً فقط).
- التلاميذ: إضافة، تعديل، أرشفة، بحث، استيراد جماعي بالنسخ واللصق مع معاينة وتجاهل المكرر.
- الحضور (حاضر / غائب / متأخر / رخصة / إعفاء)، الحصص، التقرير اليومي مع القفل النهائي ومراجعة الإدارة.
- ملاحظات التلاميذ (تصنيفات موسّعة، حالة متابعة، ملاحظات صحية للكاتب والإدارة فقط).
- الدفتر الخاص بالمدرب (معزول بـ RLS)، الإعلانات، السجلات الطبية (للإدارة فقط)، سجل التدقيق.
- محادثات فردية وجماعية، تحديث فوري، صور وملفات وتسجيل صوتي، تخزين خاص.
- PWA، العربية والفرنسية والإنجليزية (RTL للعربية).

## مضاف في قاعدة البيانات في هذه النسخة (الواجهة لم تُربط بعد)
- حالة الحساب `rejected`.
- حالة قراءة الرسائل وعدّاد غير المقروء: `mark_conversation_read()` و `unread_counts()`.
- إدارة أعضاء المجموعات: منشئ المجموعة يضيف، والعضو يغادر، والمنشئ أو الإدارة يزيل.
- علامة متابعة العودة بعد 5 غيابات متتالية: جدول `absence_followups` ودالة `mark_followup_handled()`.
  - "المتتالية" تُحسب على الحصص الفعلية للمؤسسة (تواريخ فيها تسجيل حضور) وليس على الأيام التقويمية.
  - تبقى العلامة خلال حصتين فعليتين بعد العودة (حصة العودة تُحسب الأولى).
  - احتساب الرخصة/الإعفاء/الواجب كغياب قابل للضبط: `institutions.count_permissions_as_absence` (الافتراضي: لا).
  - حدّ معروف: تعديل حضور قديم بأثر رجعي لا يعيد حساب العلامات تلقائياً.

## غير منجز (يحتاج عملاً إضافياً)
- ربط الواجهة بما سبق (إظهار علامة المتابعة، عدّاد غير المقروء، إضافة/إزالة أعضاء المجموعة، تصنيف الملاحظات الجديد).
- تقسيم `src/App.tsx` (ملف واحد ضخم) إلى مجلدات components / pages / features / hooks.
- اختبارات آلية (Unit / Integration) وLint. الموجود الآن فحص ثابت `npm run verify` فقط.
- مرفقات التقارير والملاحظات، وتحديد مستلمي الإعلانات وحالة قراءتها.
- بحث داخل المحادثات، وحالة الإرسال.
- Web Push الفعلي.
- `package-lock.json`: يُنشأ تلقائياً عند أول `npm install` ويجب رفعه إلى GitHub.

## قرارات موثّقة
- 4 أدوار (owner / manager / admin / coach) بدل 3، والمدير والإداري يتقاسمان صلاحيات الإدارة.
- التقرير اليومي يُرسل مباشرة ويُقفل (submitted ثم reviewed)، ولا توجد حالة Draft في الواجهة الحالية.
- منع تداخل الحصص: حصة مفتوحة واحدة فقط لكل مدرب (فهرس فريد).

## لم يُجرَّب
لم يُنفَّذ `npm install` ولا `npm run build` ولا SQL على PostgreSQL ولا RLS على Supabase حقيقي. هذه الخطوات تتم عندك (انظر README و docs/ACCEPTANCE_TESTS.md).
